# Contributing to Python Practice Repository

Thank you for contributing to **Python Practice Repository**!

This repository is a structured Python learning resource for beginners, intermediate learners, and experienced developers who want to practice or revise Python. Contributions are welcome as long as they are useful, educational, and follow the existing structure.

> **Goal:** Every contribution should help someone learn, practice, or improve Python.

---

## Before Contributing

- Check the repository first to avoid duplicates.
- Fit your contribution into the correct, existing section.
- Follow the folder and naming structure already in place.
- Keep code clean, readable, and educational.
- Include a clear explanation.
- Avoid unnecessary dependencies.
- Use original content, or give proper attribution.

## Sections 01-17

Every section from 01 to 17 follows the same 5-subfolder pattern:

```text
01. Basics(Main Folder Name)/
│
├── 01. Programming/
├── 02. Programming/
├── 03. Programming/
├── 04. Programming/
└── 05. Mini Challenges/
```

The exact names of the first four folders vary by section, follow the naming already used there rather than forcing a fixed pattern.

**Programming folders:**

- Each of the first four folders must contain **exactly 10 programs**.
- Do not add an 11th regular program.

**Mini Challenges:**

- `Mini Challenges` has no limit, add as many relevant challenges as you like.
- Keep challenges relevant to the section.

## Section 18 - Projects

`18. Projects` is for larger, practical Python projects that combine concepts learned across the repository. There's no 10-program restriction here.

Projects may cover areas such as:

- Automation
- APIs
- CLI applications
- Data processing
- OOP
- Games
- Utilities
- Productivity tools
- Other practical Python applications

You may create additional folders inside `18. Projects` when it genuinely improves organization.

## Notes and Learning Resources

You're welcome to add notes, explanations, examples, diagrams, cheat sheets, references, or topic summaries. Keep them accurate, clear, organized, and relevant.

## Program Requirements

A good program should include:

- A clear title
- Clean, readable Python code
- Meaningful variable/function names
- Comments where helpful
- A useful explanation
- Beginner-friendly logic where appropriate
- No unnecessary complexity

**The explanation matters as much as the code.** Where relevant, explain:

- What the program does
- How it works
- Why the approach is used
- How variables are initialized and values move through the program
- How loops/conditions are evaluated
- What key functions or concepts are doing
- What the learner should take away from it

> Don't just provide the code, help the reader understand the code.

## Contribution Workflow

1. **Fork** the repository to your GitHub account.
2. **Clone** your fork:

```bash
   git clone https://github.com/YOUR-USERNAME/Python-Practice-Repository.git
   cd Python-Practice-Repository
```

3. **Create a branch** (don't work directly on `main`):

```bash
   git checkout -b your-contribution
```

4. **Add your contribution** to the correct location.
2. **Test your code**, check for syntax errors, incorrect output, unused imports, broken paths, and unnecessary dependencies.
3. **Commit** with a clear message:

```bash
   git add .
   git commit -m "Add function practice programs"
```

7. **Push** your branch:

```bash
   git push origin your-branch-name
```

8. **Open a Pull Request** to `main`, briefly explaining what you added, where, and why it's useful.

## Pull Request Checklist

- [ ] Followed the existing folder structure
- [ ] Added to the correct section/folder
- [ ] Checked for duplicates
- [ ] Code tested and working
- [ ] Code is readable
- [ ] Explanation included
- [ ] Program-count rules followed
- [ ] No unnecessary dependencies
- [ ] Original content or proper attribution
- [ ] Clear commit message
- [ ] PR description explains the contribution

## Other Ways to Contribute

You don't have to add new programs. You can also:

- Fix bugs
- Improve or correct explanations
- Improve code readability
- Add helpful comments
- Improve notes or documentation
- Add meaningful examples
- Improve existing projects
